📖 What is Programming?

Imagine you have a robot assistant. Programming is simply writing instructions that tell the robot exactly what to do.

For example, if you wanted to tell your robot to make tea, you'd write something like:

English1. Boil water
2. Put tea bag in cup
3. Pour water into cup
4. Wait 3 minutes
5. Remove tea bag
6. Add sugar if wanted

That's programming! A computer is your "robot" — and the instructions you write are called code.

Let's Understand Every Line

Line 1: module littlestar:

This tells the computer: "Hey, this is a Littlestar program!"

Think of it like writing your name at the top of a test paper. Every Littlestar program must start with this line.

Line 3: spark main(1):

This creates a code block — a container for your instructions.

  • spark means "create a block"
  • main means "this is a main block"
  • (1) means "this is block number 1"
  • : means "here's what's inside"

Think of it like a chapter in a book: "Chapter 1 begins here."

Line 4: display("Hello, World!")

This is the instruction that actually does something! It tells the computer to show the text "Hello, World!" on screen.

  • display is a function — a command that does something
  • ("Hello, World!") is the message you want to show
  • The quotes "..." tell Littlestar "this is text, not code"

Lines 6-7: spark print: and main(1)

This tells Littlestar which blocks to run and in what order.

Think of it like a playlist: "Play chapter 1."

⚠️ Important Rules (Remember These!)
  • Every program MUST start with module littlestar:
  • Every program MUST end with a spark print: block
  • Code inside blocks must be indented with 4 spaces (or press Tab)
  • Block numbers must go in order: 1, 2, 3...

2 Program Structure

Every Littlestar program follows the same basic recipe, like a sandwich:

Structuremodule littlestar:            ← TOP BUN (always first)

    spark main(1):              ← FILLING (your code)
        # your code goes here

    spark main(2):              ← MORE FILLING (optional)
        # more code here

    spark print:                ← BOTTOM BUN (always last)
        main(1)
        main(2)

Multiple Blocks

You can organize your code into multiple blocks, like chapters in a book:

Littlestarmodule littlestar:

    spark main(1):
        display("=== Chapter 1 ===")
        display("Once upon a time...")

    spark main(2):
        display("=== Chapter 2 ===")
        display("The adventure continues...")

    spark main(3):
        display("=== Chapter 3 ===")
        display("The End!")

    spark print:
        main(1)
        main(2)
        main(3)
=== Chapter 1 === Once upon a time... === Chapter 2 === The adventure continues... === Chapter 3 === The End!
💡 Why Multiple Blocks?
  • Organization — keep related code together
  • Order control — choose which blocks run and when
  • Selective running — skip blocks by removing them from spark print:

5 Comments

Comments are notes for humans — the computer ignores them completely. They help you (and others) understand your code.

Inline Comments (one line)

Use # to start a comment. Everything after # on that line is ignored:

Littlestar# This is a comment — the computer ignores this!
display("Hello")  # This comment is after code
Hello

Block Comments (multiple lines)

Use !! to wrap a multi-line comment:

Littlestar!!
This is a block comment.
It can be as many lines as you want.
The computer skips all of this.
!!
display("I'm the only code that runs!")
I'm the only code that runs!
💡 When to Use Comments
  • Explain why you wrote something (not what — the code shows what)
  • Leave notes for your future self
  • Temporarily disable code without deleting it

8 Declaring Variables

To create a variable, use the declare keyword:

Littlestarmodule littlestar:

    spark main(1):
        declare name = "Alice"
        declare age = 25
        declare score = 98.5
        declare isHappy = yes

        display("Name: " + name)
        display("Age: " + age)
        display("Score: " + score)
        display("Happy: " + isHappy)

    spark print:
        main(1)
Name: Alice Age: 25 Score: 98.5 Happy: true

Naming Rules

  • ✅ Use letters, numbers, and underscores: myName, score_1, player2
  • ✅ Start with a letter: age, userName
  • ❌ Don't start with a number: 2name is wrong!
  • ❌ No spaces: my name is wrong! Use myName
  • ❌ Don't use Littlestar keywords: display, when, etc.

9 Updating Variables

After declaring a variable, you can change its value using set:

Littlestarmodule littlestar:

    spark main(1):
        declare score = 0
        display("Starting score: " + score)

        set score = 10
        display("After first round: " + score)

        set score = score + 5
        display("After bonus: " + score)

        set score = score * 2
        display("After doubling: " + score)

    spark print:
        main(1)
Starting score: 0 After first round: 10 After bonus: 15 After doubling: 30
❌ Common Mistake You MUST declare a variable before you can set it! 
set name = "Alice"   # ❌ ERROR: 'name' was never declared!
declare name = "Alice"  # ✅ CORRECT: declare first
set name = "Bob"        # ✅ Now you can change it
ℹ️ declare vs set
  • declare — creates a NEW variable (first time only)
  • set — changes an EXISTING variable (must be declared first)

23 Multiple Choices with elif

When you have more than two options, use elif (short for "else if"):

Littlestarmodule littlestar:

    spark main(1):
        declare score = 85

        when score >= 90:
            display("🏆 Grade: A — Excellent!")
        elif score >= 80:
            display("🌟 Grade: B — Great job!")
        elif score >= 70:
            display("👍 Grade: C — Good")
        elif score >= 60:
            display("📝 Grade: D — Needs improvement")
        otherwise:
            display("❌ Grade: F — Failed")

    spark print:
        main(1)
🌟 Grade: B — Great job!

Littlestar checks each condition from top to bottom. It runs the first one that's true, then skips the rest.

28 Loops — Repeating Things

Imagine writing "I will not talk in class" 100 times. Would you write it by hand? Of course not — you'd use a loop!

A while loop repeats code as long as a condition is true:

Littlestarmodule littlestar:

    spark main(1):
        declare i = 1
        while i <= 5:
            display("Line " + i)
            set i = i + 1

    spark print:
        main(1)
Line 1 Line 2 Line 3 Line 4 Line 5

How It Works (Step by Step)

  1. declare i = 1 → Start at 1
  2. while i <= 5: → Is 1 ≤ 5? YES → run the body
  3. display("Line " + i) → Print "Line 1"
  4. set i = i + 1 → i becomes 2
  5. Go back to step 2. Is 2 ≤ 5? YES → print "Line 2"
  6. ...continues until i becomes 6
  7. Is 6 ≤ 5? NO → loop stops
❌ Infinite Loop Warning! If you forget set i = i + 1, the loop runs FOREVER because i stays at 1 and 1 <= 5 is always true. Littlestar protects you by stopping after 10,000 iterations.

Littlestardeclare i = 0
while i < 10:
    set i = i + 1           # ← IMPORTANT: increment BEFORE skip!
    when i == 3 or i == 7:
        skip                # ← Skip 3 and 7
    display(i)
1 2 4 5 6 8 9 10
⚠️ Critical Rule for skip Always put set i = i + 1 BEFORE the skip statement! Otherwise the loop will hang because i never changes. 
# ❌ WRONG (will hang!):
while i <= 5:
    when i == 3:
        skip
    set i = i + 1    # Never reached when i==3!

# ✅ RIGHT:
while i < 5:
    set i = i + 1    # Always runs!
    when i == 3:
        skip

42 What Are Functions?

A function is a reusable block of code. Think of it like a recipe — you write it once, then use it whenever you need it.

Instead of writing the same code 10 times, you put it in a function and call it 10 times!

✅ Best Practices

  1. Use descriptive variable names: totalPrice not tp
  2. Add comments to explain WHY you did something
  3. Indent properly — 4 spaces for each level
  4. Use declare for variables, letarr for arrays, fix for constants
  5. Test your code often — run after every few lines
  6. When using skip in loops, always increment BEFORE the skip
  7. Use decimals() for money formatting
  8. Use comma() for large numbers
  9. Break code into functions when it gets long
  10. Use multiple spark main() blocks to organize your program
